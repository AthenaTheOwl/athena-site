A workspace gives a task its own checkout to edit. The parent can review its diff before integrating it. Git worktrees provide that separation without a workspace service.

They isolate file changes. They do not isolate the network, operating-system user or credentials.

## The worktree primitive

Git lets one repository have several working directories on separate branches. Assigning a branch and directory per task reduces accidental edit collisions. Integration still needs review and conflict handling; a branch is not a lock on every resource the task can reach.

Tool-specific worktree controls vary. The portable contract is the checkout, base revision and resulting diff, not a promise that exiting an agent tool automatically merges or safely discards its work.

## What the factory does

Procurement-negotiation-lab implements its helper in `scripts/factory/worktree.py`. `create_worktree` returns a path, task branch and base branch. The branch is `factory/<task-id>`; the checkout is a sibling named `<repo>-task-<task-id>`.

The helper can reuse a registered worktree. It does not install dependencies, copy environment files or write a `WORKSPACE.md` manifest. Those would be separate setup choices. Naming a helper `factory` does not make every desirable step appear inside it.

## A concrete example

The factory pipeline resolves the worktree before running workers. Its documented flow is plan, implement, gates, review, then commit and optional publication, with configured human checkpoints. Artifacts and task state identify what happened when a run pauses.

Dry-run and stub output are useful for testing the orchestration. They are not evidence that an agent completed the requested product change. The record needs to say which worker ran.

## Why no workspace-manager service

A directory and branch can be enough while tasks are few and the parent can track ownership. Add a manager when allocation, recovery or cleanup becomes a measured failure source. A daemon is one possible response; it is not an admission threshold set by headcount.

Keep secrets and privileged services outside the task's reach unless the work needs them. Preserve needed changes before cleanup. A second checkout prevents one class of collision, and that is a useful claim without promoting it to a sandbox.
