A dream is an offline run that reads prior work and proposes changes: memory updates, tests, skill patches or backlog items. The shared contract is `ops/schemas/dream-output.schema.json`. Outputs belong under `dreams/<week>/`.

The output is a candidate. Frequency is not promotion authority.

## What a dream run does

The schema names seven modes: memory consolidation, failure clustering, adversarial simulation, skill extraction, golden-test generation, prompt patch generation and architecture drift detection. The run records its scope, lookback period, sources, report path and candidates.

Each candidate carries evidence and an explicit `human_review_required` flag. The schema gives that boolean a default of true; it does not require its value to be true. A promotion gate has to enforce the human-review policy separately. A default in a schema is not a reviewer's signature.

Weekly is a useful cadence for the operating model. A directory from one week proves an output exists, not that a scheduler ran every week or that every mode ran.

## A concrete example

Procurement-negotiation-lab's `dreams/2026-W21/report.md` records five candidates: three memory updates and two regression-test proposals. It reports no extracted skill, because the pattern had not met its recurrence bar.

One candidate, `memory-002-factory-worktree-isolation-as-convention.md`, points at the factory's worktree implementation and decisions. It proposes using one branch per multi-step task, while preserving an exception for small edits because a second checkout has a cost. The candidate's frontmatter records human review and its promotion status. Those are observable records; they do not establish that the convention prevents every collision.

The report also lists modes it skipped and conditions for reopening them. That is useful output. A run need not invent a lesson to fill each mode.

## Why an offline job

The online request pays for every extra second. An offline job can spend more time comparing traces, but still needs a budget. Moving a long pass to Sunday does not make its tokens free.

Keep the input record, write the proposed change separately and preserve the evidence for accepting or rejecting it. A recurring mistake can become a test; a recurring false assertion can become a more confidently filed false assertion. Consolidation needs the provenance it is tempted to compress.

## What to audit

Count scheduled runs that completed, candidates generated, candidates reviewed and candidates promoted. Keep those denominators separate. A report with five candidates and no reviews is a queue, not five improvements.

After promotion, measure whether the candidate changed the failures it named. Otherwise the loop has measured its own productivity in new files.
