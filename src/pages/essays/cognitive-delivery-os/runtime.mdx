A runtime record describes one agent run: its target spec, worker, workspace, start time and status, with optional costs, outputs and replay evidence. The shared contract is `ops/schemas/run.schema.json`. Individual ledger entries use `ops/schemas/event.schema.json`.

A run summary and an event stream are related records. They are not the same schema with different line breaks.

## What the records carry

The Run schema requires `id`, `spec_id`, `agent_id`, `runtime`, `workspace_id`, `started_at` and `status`. Optional fields include inputs, outputs, costs, events, prompt and tool-schema hashes, a checkpoint reference and a sandbox reference.

An Event requires `event_id`, `type`, `created_at`, `actor` and `payload`. `run_id` links an event to a run when applicable. The event vocabulary is documented in `ops/event-types.md`.

Some event types have typed payload checks; others receive only envelope validation. Passing the envelope does not establish that the tool-specific payload is complete. Likewise, a missing optional cost is an unknown cost, not zero.

## A concrete example

Procurement-negotiation-lab's factory documents two outputs: ledger lines under `ops/event-ledger/<run-id>.jsonl` and a final summary under `ops/run-records/<run-id>.json`. Its internal task state lives in SQLite; artifact content lives in files referenced by the events.

That is a real division of labour. The event stream records transitions, the Run record names the attempt, and the artifact reference locates what it produced. None alone is a complete replay environment.

## Why files, and when a database helps

JSONL is easy to search and archive. SQLite can answer joins over task state and events without loading every file. Choose by access and recovery needs, not a rule that a solo builder must never use a database.

Neither format makes a record append-only by itself. Protect the writer and the retained evidence. A valid digest proves byte consistency against an anchor; it does not prove a tool executed the command recorded.

## What to audit

Check runs that never reached a terminal status, calls missing results, produced artifacts missing gate evidence, and costs or timings absent from a report that claims to summarize them. Compare tool results with resulting state where the action matters.

A started run without a completion event may be a crash, an incomplete log or work still running. Preserve the distinction until the surrounding evidence settles it. A missing row is not a diagnosis.
