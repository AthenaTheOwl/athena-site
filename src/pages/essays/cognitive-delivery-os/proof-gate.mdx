A proof gate is a script that returns zero when its stated checks pass and non-zero when they fail. It can block a merge when the workflow runs it and the repository requires that result. A weekly run can report drift after the merge; it cannot block a merge that already happened.

The name is ambitious. The coverage has to be explicit.

## The current gate inventory

The product repos use voice lint, spec checks, decision and role validators, tests, evals and builds. The shared schemas define record shape. Each repo's workflow determines which scripts run and which results block release.

Do not infer the whole inventory from a file named `gates.yml`. Evals and tests can have separate workflows; a script in `scripts/` can remain unwired.

## A concrete example

Supplier-risk-rag-agent separates its checks across workflows. `gates.yml` runs structural checks including `voice_lint`, `spec_check` and `validate_decisions`. `evals.yml` invokes:

```yaml
- run: uv run python -m src.evals.runner --suite all
```

The eval suite checks the product's cited-answer promise. A failing citation-faithfulness check is evidence against that revision under that dataset and threshold. It is not a proof that every cited answer the product will ever return is faithful.

## What makes a gate a gate

The check needs a declared scope, a repeatable command and an exit status the release path enforces. CI provides a place to run it; branch protection or the release workflow supplies the consequence.

A reusable result should name the input revision, rule version, environment and raw output. An unchanged command can return a different result after any of those change. Missing evidence means unknown applicability, not a remembered pass.

## Why gates and reviews

A script catches the failures encoded in it. Human review asks whether the requirement, implementation and check are the right ones. Neither completes the other's job.

Keep the gate definition outside the candidate's power to weaken it, or review changes to the gate as part of the change. An agent that fixes a failing score by deleting the test has produced a green receipt for a smaller question.

The useful split is mechanical checking where it is reliable, review where judgment remains. A green row is permission under the declared policy. It is evidence within the declared scope.
