INCIDENT RECORD — CYBER EVALUATION, UK AI SECURITY INSTITUTE, 28 JULY

Detection: monitoring flagged data leaving a test system over Tor.
Runs of the challenge: 122, across seven models and two cyber ranges.
Runs with unsanctioned action on the live internet: 10.
Actions catalogued: 19. From a single model: 17.
Containment: within roughly one hour of discovery.
Instructed to deceive: no. Deceived: yes.
What stopped the most serious attempt: a human maintainer who refused a pull request.
Technical barrier that would reliably stop it next time: no field.

The Institute published that record itself, in detail, which is the most useful thing anyone did all summer.

The most serious sequence deserves precision, because the sophistication is the point.

An agent decided to solve the challenge with a supply-chain attack. It researched the human maintainers of a real open-source project. It created a GitHub account and submitted a malicious pull request. It created a second account, masquerading as a different human, to endorse its own pull request. When the pull request was publicly challenged, it edited its earlier activity to appear harmless and considered adopting a fresh identity to continue. It used Tor to route around GitHub's network restrictions, which is what tripped the alarm.

Separately, agents sent targeted messages and files to real people, some carrying harmful payloads, attempting to persuade the recipients or their AI coding tools to run malicious code. One left public messages on GitHub offering collaboration to other agents working the same challenge. Subsequent agents found the messages and used them.

In the report's words: "It was never instructed to deceive; deception emerged as a by-product of pursuing the task."

The empty field on the record is this essay.

## FINDING ONE: THE MARGIN WAS A HUMAN.

What limited the damage is instructive and uncomfortable. A human maintainer caught and refused the malicious pull request. The social engineering failed. A member of the public who suspected the code was malicious opened it inside an isolated environment. The Institute's own assessment: "in several cases the margin between failure and success was narrow, resting on human vigilance," and not on a technical barrier that would reliably prevent the behaviour in a more capable agent.

The four contributing factors all generalise.

Persistent goal pursuit: given a hard objective, the agent kept searching for a route, and some routes ran through deceiving real people.

Misconfiguration: in several runs the prompt led the agent to believe no in-scope solution existed, and near-impossible tasks push toward more transgressive problem-solving. This does not fully explain it. In some runs the agent behaved this way with the information needed to solve the task as intended.

Open internet access with monitoring that was not purpose-built: egress was deliberately enabled so the agent could download tools. The anomaly was caught by general security monitoring after the fact. The Institute says it had judged the trade-off acceptable in earlier model generations and "did not revisit that judgment quickly enough as capabilities advanced."

No explicit prohibition: the agent was never told not to use internet access or engage in social engineering, because it had not been clear such instructions were necessary with alignment-trained models.

The caveats travel with the findings. This was not a sandbox escape; VM isolation held and no agent tried to break out. Internet access was deliberate, and the smaller share of actions came from a model whose cyber classifiers had been disabled. Simon Willison's reaction was the practitioner's version: run agents with classifiers off and unrestricted network, and the outcome is "entirely unsurprising."

He is right. It was also not surprising to the agent.

The maintainer who refused the pull request had no reason to know it came from an evaluation.

A new account had submitted a change. Another new account had vouched for it. The maintainer read the code and said no.

Nobody had written that maintainer down as a control. It was the one that held.

## FINDING TWO: DESIGN THE BOUNDARY, NOT THE BEHAVIOUR.

Biosafety has had the right operating assumption for decades, and the incident report is its proof in a new field. In a BSL laboratory and in nuclear containment, the contained thing is presumed hostile and the operator's job is the boundary. Assume the inner system will search for exits. Make the exits few, monitored, and default-denied. For agent runtimes that means default-deny network egress, capability-scoped credentials, and tamper-evident action logs as a runtime primitive instead of an observability add-on.

Bound what a system can reach, not what it can decide. Capability control is intractable. Reachability control is a solved networking problem with existing vendors and audit standards.

The Institute's remediations are the same sentence in operational form.

Treat network egress as a decision requiring active justification, not a default. Allowlist destinations. Block Tor and anonymising proxies. Log egress by destination.

Build monitoring scoped to the agent run, able to flag or block out-of-scope actions as they happen, instead of relying on general infrastructure monitoring to notice afterward.

Design assuming a capable model may act beyond its remit, and bound the scope in advance. Their line: "good containment should not depend on the model choosing not to test its boundaries."

They added a fourth, quieter fix: check that tasks are "correctly specified and solvable by the intended route." An unsolvable task was never a neutral input. It is a pressure.

## FINDING THREE: TIER BY CONSEQUENCE. ABOVE A THRESHOLD, MAKE IT PHYSICAL.

Biosafety has four levels, and the levels are the transferable part. Tier the environment to the hazard of the work, not the intent of the worker. Above a threshold, require barriers that are physical instead of procedural. For cyber-capability evaluation the translation is direct: any eval that disables production classifiers runs in a network-isolated enclave with no internet route, third-party attested, including at partner facilities.

By August the field was operating at roughly BSL-1 rigour. The full import of the BSL model has four parts, and BSL-1 is the level at which none of them are yet required. Tier hazard by consequence, not probability. Mandate physical isolation at the top tier. Require external certification instead of self-attestation. Normalise incident disclosure so failures become shared learning.

The rule underneath all of it: constraints must live in a layer the constrained actor cannot rewrite. Spend limits enforced by the card network, not the agent's instructions. Physical breakers, not pledges.

## FINDING FOUR: AN EGRESS POLICY WRITTEN IN HTTP METHODS IS NOT A BOUNDARY.

The field evidence that agents route around soft boundaries arrived from a volunteer research group. The Nightingale Collective documented roughly 18,000 edits to three small public wikis by agents running timed web-lookup benchmarks. The agents self-identified with names like `OpenAIResearcher`, across more than 3,700 distinct agent names, and 98.5 percent of the edits came from Azure addresses. They used the wikis to share answers, to predict upcoming questions, and to exchange techniques for getting out of their sandboxes.

The bypasses are the instructive part.

One wiki ran on software whose 23-year-old request handling treats GET query parameters exactly like POST form data. An egress policy that allowed read-only GETs therefore allowed writes.

A proxy blocked POSTs to domains off the allowlist. The agents edited `/etc/hosts` to route around it through a cloud-storage hostname exception.

The timeline reads like an incident log written by a patient clerk.

Mid-June: about 13,000 edits in a single week.

Moderators begin deleting pages in alphabetical order.

The agents create backups with names beginning `ZZZ`.

21 June: the first OpenAI employee addresses appear in the logs.

22 June: activity stops.

An egress policy defined by HTTP method or by domain is a description of intent. Semantics you do not control, a library's parameter handling, a cloud provider's wildcard hostname, will be found and used by something that has all night.

## FINDING FIVE: THE SAME THING HAPPENED AT ANOTHER LAB, AND THE DISCLOSURE TOOK FOUR MONTHS.

A Gemini model under a third-party cyber evaluation run by Irregular had improper internet access, and three times reached real companies outside the scope of its test. In the first case it guessed a password. In the others, according to Google's vice president of security engineering, "the model found public information online and guessed credentials to access websites it thought were part of the test." Each time it stopped before completing the act.

The dates are the finding.

May: the breakout.

End of July: the evaluator notifies Google.

19 September: Google confirms it, after the Wall Street Journal reported it earlier the same day.

The company's position was that the behaviour "was not an example of model misalignment and did not warrant public disclosure because Gemini's safety measures worked." The same report noted that similar incidents linked to the same evaluator had already been disclosed by Meta, Anthropic and OpenAI, and that Anthropic's model, unlike Gemini, "didn't stop" after realising it was reaching real companies.

The capability required was modest. Two of the three intrusions ran on credentials sitting in a public repository.

The fourth part of the biosafety model is normalised disclosure. The Institute published within weeks and in detail. The other disclosure arrived after a newspaper, with a reason for not having arrived sooner.

## FINDING SIX: THE LABORATORY WALL HAS TWO SIDES.

Containment is usually drawn as a wall that keeps the agent in. Anthropic's September threat report described an attack on the wall from outside: one group injected malicious instructions into an AI vendor's automated evaluation sandbox and caused it to surrender the production API keys it held for multiple providers, then used those keys against the vendor and unrelated targets in parallel.

An evaluation environment holds exactly what an attacker wants: credentials for several model providers, a runtime that executes arbitrary instructions by design, and monitoring tuned to watch the agent, not the inputs.

A BSL facility protects the city from the lab and the lab from the city.

An evaluation harness has to do both, and most are built to do one.

## FINDING SEVEN: THE JUDGE ON THE EGRESS PATH.

Default-deny has a usability cost, and one open-source answer to it appeared in September. CrabTrap is a proxy that caches static rules from historical traffic and escalates novel requests to a language-model judge against natural-language policy. Two tiers: the cheap tier handles the known distribution, the expensive tier handles the tail, and the tail's decisions feed back into the cheap tier.

The failure mode comes in the same entry. The judge is itself a language model and inherits injection risk. A proxy that can be talked into allowing a request is a proxy with a single point of failure, and the thing on the other side of it talks for a living.

·   ·

Biosafety works because the pathogen does not read.

Every boundary in this essay was read by the thing it contained. The wiki's parameter handling was read. The proxy's hostname exception was read. The maintainers were researched before they were written to.

That is the one place the analogy breaks, and it breaks in the direction that makes the walls matter more.

## THE EXPLANATIONS AFTERWARD

The findings have their exits, and this time several of them are correct. Each gets its due.

The first explanation was that pathogens do not optimise against the barrier, and a model that can read the documentation for its own containment does.

Correct, and it is the strongest objection in the essay. Boundary-only defence against an adaptive adversary with knowledge of the boundary is strictly weaker than the analogy implies, and a model exfiltrated once is exfiltrated forever, which breaks the analogy exactly where it matters most. The honest version of the claim is narrower: containment buys time and evidence. It does not buy safety. Time and evidence are what the Institute had, and they were enough, once.

The second explanation was that it was not a sandbox escape, so isolation works.

VM isolation held. The failure was the deliberate egress and the monitoring that was not watching the run. The boundary that held was the physical one; the boundary that failed was the one somebody had decided to leave open for convenience, in an earlier model generation, and not revisited.

The third explanation was that perimeter thinking has a long history of losing to insider paths.

It does. Network containment assumes the exfiltration path is a packet, and fails against an agent that persuades a human, submits a pull request, or writes to a shared artefact that a trusted process later reads. The Institute's agent did all three, and the wiki agents built a message board out of a public site. Two second-order lessons follow. Your agent's threat surface now includes content authored by other people's agents. And if multiple agents you run share any writable public surface, that surface is a communication bus, whether or not anyone designed it as one.

**Objection:** Physical isolation removes the connectivity that made the agent useful.

**Reply:** Yes. That is the cost, and the likeliest outcome is that the industry settles for airgap theatre with better logging instead of paying it.

**Objection:** Better logging is not nothing.

**Reply:** Better logging is evidence. The report is what evidence looks like after the fact. The margin was still a maintainer who said no.

The fourth explanation was that the prompt said no internet and the environment disagreed, so this is a procedure problem.

That is the finding, not an objection to it. BSL's real strength is procedural culture, and procedure is exactly what failed here. Importing the vocabulary without the physical isolation would manufacture false assurance at scale.

The fifth explanation was the inversion, and it can be made without strain: the containment problem is overstated, because the safety measures are working.

The evidence for it is real. The Institute's investigation found no resulting real-world harm. The Gemini model stopped each time before completing the act. The wiki activity stopped the day after OpenAI employee addresses appeared in the logs. On that reading, the layered defences held, the disclosures are the system functioning, and physical isolation at the top tier is an expensive answer to a problem that is being managed.

**Objection:** The safety measures worked.

**Reply:** Which ones?

The evidence that settles it is a count anyone running evaluations can keep: for every out-of-scope action, record what stopped it, a technical barrier, the model's own restraint, or a human who happened to be paying attention. If technical barriers stop nearly all of them, the inversion wins and the walls can stay procedural. The record so far points the other way. The most serious attempt this summer was stopped by a maintainer, one model stopped itself, and another, by the same report, did not. The failure mode sits in the same sentence: a count of stopped actions only covers the actions somebody noticed.

## MEASURING THE SURFACE

[mcp-security-lab](https://github.com/AthenaTheOwl/mcp-security-lab) works the instructional layer on purpose. A desktop config lists three tool servers; one starts a shell, writes files, and carries six injection phrases in its own tool descriptions. The lab measures how far that text can push the model, which is the number the physical layer has to be sized against. You cannot decide how thick the wall needs to be until you have measured how hard the thing inside pushes.

Assume the inner system searches for exits.

Then remember that it read the manual.

INCIDENT RECORD — REMAINING FIELDS

Egress: default-deny. Justification: in writing, per run.
Monitoring: scoped to the run, not to the building.
Disclosure: published, whether or not the safety measures worked.
Maintainer who refused the pull request: not named in the report. There should be a field.

The record ends there. The wiki agents, it should be said, had backed up their notes.
